# 外装ニュース：試用とヒアリング

## 初期設定

- 内装の既存URLを維持し、外装は `http://IEWEB01/exterior/` に公開。
- 対象はグリル・バンパー・外装加飾・エンブレム・発光・センサー透過・ウェザーストリップ等。地域は日本・中国・インド・米国・欧州。
- 記事不足時は件数を補うために対象外を採用しない。取得成功で該当なしの日と、取得失敗を区別。
- 外装へのアクセス数、記事閲覧、いいね、コメント、お気に入り、アカウント、メール購読は内装から独立。
- 社内ネットワークから外装URLを開くだけで閲覧可能。メールを受信する必要はなく、外装アカウントを登録しただけでも自動配信しない。受信チェックは初期オフで、希望者が登録画面またはマイページでオンにする。
- メールは月～金の朝8時に配信。購読変更は2分間隔で宛先JSONへ同期し、通常は次回同期まで最長約2分で反映する。OneDrive同期時間も加わるため、8時直前の変更は当日の配信に間に合わない場合がある。
- 初期配信先は私有の名簿に登録した管理者1名。氏名・メールアドレス・認証値は設定ファイルやGitへ追加しない。
- 元記事の写真は利用し、AIによる企画画像の生成は停止（`provider: "none"`）。有料画像生成を使わず、文章の考察・企画アイデアを提供する。exaBaseは将来の追加候補。

## メンバーへのヒアリング（1週間程度の試用後）

### 初回の内容確認で残した課題

初回は収集対象日2026-09-14の枠に2記事を採用し、2地域の考察と4案を作成した。材料の帰属、出典リンク、事実と仮説の区別を校正済み。

画面の日付は現行収集処理の対象日で、原文の掲載日時と一致しない場合がある。例えば初回の国内記事は、RSSのUTC日付が9月14日、原文の日本時間の掲載日は9月15日だった。今後、収集の区切りと原文掲載日を分け、日本時間への日付正規化と取得漏れへの影響を内装と併せて確認する。日付を原文の日本時間での掲載日と断定しない。

### 確認する質問

1. 業務で役立った記事を3件、不要だった記事を3件。それぞれ理由は何か。
2. もっと知りたい製品・技術・企業・地域は何か。対象から外すものは何か。
3. 要約に足りない情報は何か。構造、材料、工程、性能、採用車種など、優先する項目は何か。
4. 考察・企画アイデアは必要か。実務で使うにはどこを変えたいか。
5. メールの頻度・時刻・分量は適切か。毎日／週次のどちらがよいか。
6. 検索・フィルター・お気に入りなどで困った操作はあるか。

キーワードだけでなく具体的な記事URLと理由を集め、`editions/exterior/settings.json` とプロンプトへ反映する。個別メンバーの回答や名簿は公開コンテンツに含めない。

## 公開・配信の確認

- 内装を見たあと外装を開いても、それぞれの訪問が計上される。
- 外装URLをメール購読なしで閲覧できる。外装アカウントを登録しただけでは配信対象にならず、受信オンで追加・オフで解除される。
- 購読変更後、次回の2分周期の同期とOneDrive同期を経て宛先JSONへ反映される。処理PC停止やサインアウト時には反映が遅れることも確認する。
- 外装の更新失敗が内装の成功判定や名簿を書き換えない。
- 当日実行、収集対象日、公開確認、メール送信成功、実受信を別々に確認する。
- 朝8時のフローが外装の宛先JSONを読むこと、内装の名簿を参照しないことを確認する。配信直前の購読変更は当日分へ反映されない場合がある。

## 将来のexaBase画像生成

指定された共有資料の画像生成ツールには、Edgeを操作して画像を保存するエンジン `playwright_engine.js` の `generateBatch()` がある。資料には2026-09-07の2画像生成・保存の検証記録があるが、今回DailyNewsからの生成は実施していない。

外装の設定は現在 `image_generation: {enabled: false, provider: "none"}`。exaBaseを実装する際は次を追加する。

- 各アイデアのプロンプトを順番に渡し、生成画像と出典・アイデアIDを対応づけるアダプター。
- 処理PCのWindowsユーザーでの初回ログインと期限切れ対応。別ユーザーの暗号化セッションは転用しない。
- タイムアウト・再開・重複生成防止。画像失敗時も文章の公開と通知を止めない。
- 参照画像対応は別途検証。軽量版の現行APIには参照画像の引数がない。

設定値を `exabase` に変えるだけでは利用開始できない。アダプターと実機検証を完了してから有効化する。
