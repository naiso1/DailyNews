# ご意見・削除理由と記事選定

## 利用者の操作

- 記事・アイデアの「ご意見」から投稿すると、版と対象IDが付く。サイト全体への意見はマイページから投稿する。
- マイページの「ご意見ボックス」で、自分の投稿の対応状況と対応メモを確認できる。
- 非表示にするときは「対象外／重複／誤要約／画像不一致／リンク不良／その他」と補足を指定する。
- 非表示は版内の全利用者に適用する。復元は管理者が行う。メール購読の変更とは独立している。

## 管理者の確認

マイページ → 管理 → ご意見の対応管理。

1. 種類・対応状況でご意見を絞り、未確認／対応中／対応済み／見送りを更新する。対応メモは投稿者にも表示される。
2. 理由別の現在非表示件数、非表示・理由変更・復元の履歴、月曜始まりの週次件数（JST）を見る。
3. 繰り返す指摘を読み、固定の選定ルールを確認して有効・無効を決める。自由文を自動でプロンプトやコードに変換しない。

ご意見と履歴はページ切替で確認する。週次件数は直近12週・全種類／全理由の集計で、画面の絞り込み条件とは別。2026-09-21以前の非表示は「移行時の記録」として取り込み、当時の文章・日時を保持する。移行前の復元回数や理由変更履歴は復元できない。

## 収集・公開時の動き

通常実行とCSV再開では、収集開始前にサーバーから確認済みルールと現在非表示のURLを読み取る。手元の保存先は版ごとに `runtime/<edition>/editorial_feedback_policy.json`。投稿者情報、自由記述、セッション情報は取り込まない。

- 通信失敗時は最後に成功した設定を使う。8日より古い設定はルール部分を標準設定へ戻し、既知の非表示URLは維持する。状態は実行ログに残す。
- `--build-only` は保存済み設定を使い、サーバー同期はしない。
- 非表示記事の本文URL・関連URLは次回選定から除外する。復元後は次回の同期で解除する。
- 内装の新規記事は「対象部品／技術」「新情報」「開発への参考」「原文の短い引用」を必須にする。引用の原文一致も検査する。根拠不足は1回再評価し、それでも足りなければ保留する。
- 二輪用品、消費者向けローン手続き、旅行、宇宙史などを除外する。シート単体の発売情報は除外する一方、表皮材・加飾・センシングなど具体的に応用できる情報は残す。
- 件数不足を「非対象」の記事で埋めない。10件は目標上限であり、品質条件を満たす記事が足りない日は少なくなる。
- CSVから直接公開する経路にも同じ検査を置く。新規記事の検査が通らない場合は公開前に停止する。既公開の同号記事に新しい根拠列をさかのぼって強制しない。
- 論文の既存選定は維持する。外装は既存の製品・市場情報の選定を継続し、追加の共通ルールは管理者が確認して有効にした場合だけ適用する。
- 内装の「イルミ」タグは車室内照明の文脈を確認して付ける。既存記事の画面上のタグも再判定する。

採用根拠は中間CSVの `採用根拠_*` と新規公開記事の `selection*` フィールドに保存する。根拠は生成モデルの出力を検査したものであり、内容の正しさを保証するものではない。改善後も、誤要約や見落としの指摘を確認する。

## 改善後の確認

週1回、対象外・重複・誤要約の再発例を確認する。単なる削除件数だけで良否を判断せず、掲載件数、利用者数、有用な記事を誤って除いた例も合わせて見る。

過去に削除された7件と再発した二輪2件、有用なNUGRAIN表皮材2件を検証用事例に保存した。選定条件を変えるときは、不要記事を除き、素材記事を残す両方の回帰検査を実施する。

exaBaseの参考画像入力・フォールバック・比較試験の手順は[画像生成の運用](../deployment/workstation/exabase/README.md)を参照。
