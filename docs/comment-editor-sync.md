# 自動同期でコメント入力欄が閉じる不具合

## 原因

15秒ごとの `loadInteractions()` が、いいね・コメント・非表示状態などの変化を検知すると、`applyFilters()` で記事一覧とアイデア一覧を再作成していた。これにより開いていたコメント欄のDOMが削除され、下書き・フォーカス・日本語変換状態を失っていた。既定の並び順では同じ再描画を連続して2回呼んでいた。

## 対策（2026-09-28）

- 自動更新では、開いているコメント欄、フォーカス中の入力欄、未送信の文章がある間、一覧の再描画を保留する。
- いいね・コメント・閲覧の件数とランキングは更新し続ける。
- コメント欄を閉じ、未送信の文章がなくなった時点で、保留中の並び順・表示状態を一度反映する。
- 下書きがある場合は欄を閉じても自動更新によって消去しない。送信失敗時も既存の復元処理で下書きを残す。
- 同期による二重の一覧再描画をなくす。
- 内装／外装、ニュース／企画アイデアに共通適用。自分で行うページ更新・絞り込み・画面移動をまたいだ下書き保存は今回の対象外。

## 検証

`tests/verify_ranking_comments_ui.py` は実際の共通HTML・クライアントJSを読み、APIだけを隔離したテストデータに置き換える。修正前は同期直後の「欄が開いたまま」の検査で失敗し、現象を再現した。

内装／外装それぞれ幅1400px・390pxで、ランキング、ニュースとアイデアへの入力、日本語変換イベント中の入力ノード・選択位置・フォーカス維持、下書きがある状態での開閉、送信失敗・成功、編集終了後の保留更新を確認する。15秒の定期同期も1回実際に待って確認する。投稿APIはすべてテスト内に閉じ、本番のコメント・閲覧数は変更しない。

```powershell
python tests/verify_ranking_comments_ui.py --artifacts runtime/ranking-comments-qa
```
