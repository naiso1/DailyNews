# 日本語要約が未完了の記事の扱い

収集処理はSheet2の最終補完後に、日本語化が完了していない記事だけを公開候補から外します。正常な記事が残っていれば、それらの更新を続けます。公開側の日本語チェックは維持し、未翻訳のまま掲載しません。除外によって各国の掲載件数が10件未満になる場合があります。

- `search_results.csv` の原文・URL・関連度判定は残します。除外した行の `LLM後処理` は `日本語化失敗` です。
- 同じフォルダの非公開ファイル `summary_quarantine.json` に、直近の選定で除外した件数・URL・元の日付・理由を保存します。内装は `ニュース収集/`、外装は `runtime/exterior/` です。
- 外装の `collection_result.json` は、除外後のSheet2件数と掲載元の日付を記録します。除外件数・URLも含みます。
- 選定記事がすべて未翻訳の場合は処理を失敗として停止し、以前のSheet2と公開済みニュースを維持します。「該当ニュースなし」として成功扱いにはしません。
- 日付・関連性などの条件で最初から採用記事がない外装号は、従来どおり取得成功を確認したうえで0件として処理できます。
- 論文の既存の言語例外は維持します。

## 保留記事の手動復旧

LM Studioなど通常の収集用環境を準備してから、元の記事日付を指定します。次はコマンド例です。

```powershell
& "$env:LOCALAPPDATA\DailyNewsRuntime\venv\Scripts\python.exe" -X utf8 -B `
  "ニュース収集/google_search_script.py" --dept interior `
  --repair-target-dates --repair-japanese-only --dates 2026-09-16
```

外装は `--dept exterior` に変更します。**`--repair-sheet2-only` は付けません。** 保留記事はSheet2から除外されているため、元の `search_results.csv` の指定日から復旧対象を選びます。復旧成功時は `LLM後処理` が `補完` に変わり、失敗した行は `日本語化失敗` のまま残ります。最終選定・補完も再実行するため、外装では同じ号の7日間の候補も対象になります。

この復旧コマンド自体はWeb公開やメール送信を行いません。出力されたSheet2・外装の収集結果・処理対象日を確認してから公開を再開します。すでに新しい号を公開している場合は通常runnerの対象日と一致しないため、過去日の復旧結果をそのまま `--resume-from-sheet` に渡さないでください。

今回は保留記事を毎日自動再試行する処理は追加していません。直近の隔離結果に加え、元CSVの `LLM後処理=日本語化失敗` から過去の未解決行を確認できます。
