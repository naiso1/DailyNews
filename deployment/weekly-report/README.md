# グループ別の週次利用レポート

## 構成

- `weekly_report.py`：最新社員マスタの検証、SSHで両版DBを読み取り、週ごとの所属・集計スナップショット、管理画面用JSON、HTMLメール、PNGグラフを作成。
- `export-usage.cjs`：SQLiteを読み取り専用で開く。メールはNFKC・小文字で正規化してSHA-256で照合し、氏名・メール本文・認証情報を抽出しない。
- `run_scheduled.py` / `install-task.ps1`：毎日08:35とWindowsサインイン時に集計。`pythonw.exe`と非表示SSHを使用し、黒い画面を開かない。
- `build_flow.py`：既存のOutlook・業務用OneDrive接続を参照して、停止状態の専用フロー定義を準備。週次は月曜09:00 JST、前週月曜〜日曜。テスト送信先は中村さん1名に固定。

既存の日次ニュース配信フロー・配信先は変更しない。フローの認証・作成・有効化・履歴確認には `../notifications/flow-session.ps1` を使う。

## データと定義

社員マスタは `\\tgfs1\ＩＥ開発部\90_その他\フロアー改革\電子掲示板\*/社員マスタ_YYYYMMDD.csv`。
フォルダ更新日時ではなくファイル名の日付で選び、対象日以前の最新を使う。同日異なる内容、欠損、重複はエラー。見出し名を正規化し、室・グループを識別。グループ記載のない室直属・部直属を別枠で表示する。
新しい週の名簿人数が前回から「5人または20%の大きい方」を超えて変化した場合は取り込みを保留し、前回のレポートを保持する。管理画面は集計更新から36時間経過すると古い結果であることを表示する。正当な組織変更の場合は対象範囲を確認してから運用担当が初回取り込みを調整する。

- 登録人数：共通IDを持つ内装DBの登録日から対象週末までを集計。外装の遅延作成アカウントは登録の母集団に使わない。
- 利用人数：ログインした画面利用・記事閲覧・いいね・コメントのいずれかがある人数。管理者を含む。両版合計は照合キーの集合で重複を除外。
- 利用率：利用人数 / 名簿人数。登録率も同じ母数。
- 閲覧：記事を読むクリック。ユーザー・記事・JST日付ごとに1回、端末をまたいでも重複なし。旧ブラウザ別のカウンターは維持。過去のユーザー別閲覧は復元しない。開始日を含む週は部分計測として表示。
- いいね・コメント：対象週に作成され、集計時点で残っている件数と人数。取消・削除の操作履歴ではない。
- 未ログインをグループへ割り当てない。名簿外の利用者は別枠。2026-10-01以前の版別利用人数は計測前。

`runtime/weekly-report/rosters/` に週の名簿（照合キーと所属のみ）を保存。
`snapshots/` の完了した週は初回確定後に自動変更しない。初回は当時のログと参照可能な過去の名簿を用いた再集計であり、在籍履歴そのものではない。修正が必要な場合は元スナップショットを保管し、理由を記録してから明示的に再作成する。
進行中の週は日次更新。名簿はその週の初回取り込みを保持する。

公開するのは集計値のみ。両版サーバーの非公開 `data/weekly-reports.json` に置き、管理者専用 `/api/admin/weekly-reports` で返す。名簿やレポートを静的公開・Git登録しない。

## 送信・重複防止

業務用OneDriveの `DailyNewsAutomation/weekly-report/weekly.json` と `sample.json` に配信用の本文とグラフを同期。元の名簿や照合キーは含めない。
`weekly-ledger.json` / `sample-ledger.json` は初回のみ `{"reportKey":"","state":"empty"}` で初期化。以後はクラウド側の記録を保持し、集計スクリプトは上書きしない。

フローは対象週・配信日・送信先・送信済みキーを確認し、送信前に `claimed` を記録する。送信APIの再試行は無効、フロー同時実行は1。成功後 `sent` を記録。送信応答が不明でも同週を自動再送しない。再送の判断には実際の送信・受信とフロー履歴の確認が必要。

PCが停止・未サインインで新しいレポートがOneDriveに届かない場合、旧週の誤送信を防いでスキップする。予定時刻の実行確認はクラウドのフロー履歴、集計失敗は `runtime/weekly-report/scheduled.log` を確認。週次対象データを09:00までに同期するため、集計PC・UNC・IEWEB01・業務用OneDriveへのアクセスが必要。

## 検証

2026-10-13に専用フローを作成し、週次フローを有効化。初回予定は2026-10-19（月）09:00 JST、対象週は10月12日〜18日。10月5日〜11日のサンプルを試行対象者1名へ送信。初回の添付がBase64文字列のまま保存されていたため、`base64ToBinary`でバイナリに変換して渡すよう修正し、件名に「訂正版」と明記した1通を追加送信した。実際の送信済み・受信メール、両実行の送信・台帳記録の成功、訂正版のPNGと元画像のハッシュ一致・画像表示を確認済み。元の送信台帳は保持し、訂正用の台帳を分けた。サンプル専用フローは停止済み。週次フローにも同じ添付修正を適用し、有効状態と月曜09:00の設定を確認した。定期配信の初回実行は予定日に確認する。

```powershell
node tests/test_multi_image_api.cjs
node tests/test_admin_usage.cjs
python tests/test_weekly_report.py
```

フロー作成時は既存一覧とローカル作成台帳を確認。作成POST後に応答が不明なときは一覧から照合し、同名フローを再作成しない。サンプル送信後はサンプル専用フローを停止する。週次フローの宛先は試行終了の指示があるまで増やさない。
