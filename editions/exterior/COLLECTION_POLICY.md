# 外装ニュースの収集・選別

## 2つの掲載区分

| 区分 | 対象 | 閾値・件数 |
| --- | --- | --- |
| 製品・技術 `product` | 外装部品の形状、構造、材料、機能、採用技術などの本文情報 | 60点以上。地域ごとに6件を目安に優先 |
| トレンド・マーケット `trend` | 車両デザイン、市場・需要、規制、材料、競合の具体的な変化・データ | 65点以上。地域ごとに4件を目安 |

1号あたり地域ごとに10件、5地域合計50件を目標とする。製品6件・トレンド4件は目安であり、一方が不足したら他方の適格記事で補完できる。トレンド4件は固定上限にしない。
当日優先・直近7日の補充後も記事が足りなければ10件未満で公開し、非対象や低得点の記事で件数を埋めない。
市場記事に外装部品名は必須ではないが、乗用車の企画・開発との関係を判定理由に残す。
株価だけ、値引き、電池・駆動系のスペックだけ、内装だけ、一般物流・ITなどは対象外。
トレンドから製品案を出す場合は仮説と明記し、部品の採用実績や需要量を創作しない。

CSVの `記事区分` / `トレンド分類` を、Webの `contentCategory` / `trendTopic` に引き渡す。
トレンド分類は `design`, `market`, `regulation`, `materials`, `competitor`。

## 各地域10件を目標とする選定順序

1. 地域ごとに最大60件を検討候補とし、本文を取得して関連性を判定する。候補数と採用数は分ける。
2. 号の対象日に公開された適格記事を優先する。
3. 足りない地域は、当日を含む直近7日以内に公開された未掲載記事から補う。例えば9月15日号なら9月9日〜15日のJST暦日が対象になる。
4. 元の公開日と号の日付を分けて保存する。古い記事を当日公開と表示したり、更新日時を初出日として期間内へ繰り上げたりしない。
5. 外装版の別の号で掲載済みのURL、および国や媒体が違っても同じ発表・内容の記事を除く。製品6・トレンド4の目安を柔軟に補完して最大10件とする。

不足時も関連性と点数の基準は変えない。キーワード一致だけで採用せず、市場記事では地域・対象期間・数量の範囲を確認し、外装部品の需要増へ飛躍させない。開発車の観察、記者予測、メーカー発表、過去事例の再紹介を区別する。

地域は収集元媒体の分類であり、記事が扱う市場そのものとは限らない。考察では実際の販売地域や車種用途を明示し、各地域の記事を地域全体の需要傾向と断定しない。掲載記事のある各地域に考察と2件の企画例を用意し、企画の仮説と具体的な評価方法を記す。

- 旧プロンプトは販売・市場・規制を除外し、部品語のない記事の点数を35点に制限していた。上記2区分に変更した。
- 初回の関連判定をRSSの短文だけで行っていた。外装では記事本文を取得してから判定し、取得結果を要約にも再利用する。
- 検討候補を30件から60件/地域へ増やし、トレンド候補も判定する。キーワードだけでは採用を決定しない。
- 製品検索とトレンド検索を交互に実施する。当日を優先し、不足補充の候補は直近7日の元公開日で絞る。

## 日付

外装はAsia/Tokyoの暦日で収集する。例：9月14日21:10 UTCは9月15日06:10 JSTとして9月15日に含める。
日付だけの配信情報はその日付を維持する。内装の既存日付処理は変更しない。
過去の公開記事は一括改日付しない。同一URLを再収集しても既存newsIdを保持し、別日付に重複掲載しない。
直近7日からの補充でも、記事の元公開日を号の日付へ置き換えない。例えば9月10日公開の記事を9月15日号へ初掲載する場合、記事の日付は9月10日、号の日付は9月15日として区別する。処理の実行日、号の対象日、記事の元公開日、メール送信日は別の情報として確認する。

## レビューと再評価

`runtime/exterior/collection_result.json` に取得・重複除去・判定件数、掲載区分別/地域別件数、除外理由を記録する。
`runtime/exterior/selection_review.csv` は対象日の候補と採否を確認する一覧。
履歴を含むCSV全行数を、その日の候補数として扱わない。

新しい基準で既存日付を再評価するときは、通常ワークステーション環境を読み込み、`run.lock` と単一LLMモデルの準備を確認してから次を実行する。

```text
python -B -u ニュース収集/google_search_script.py --dept exterior --dates YYYY-MM-DD --reassess-target-dates
```

対象号の既存候補と新たに収集できた候補を合わせて見直す。補充記事を含め元公開日と、他の号の掲載履歴は保持する。
過去に対象と判定した記事は判定枠から落とさず再検討するが、今回の条件を満たさなければ再採用しない。
収集だけではメール送信・画像生成・Web公開はしない。CSVとcacheのprivate backup、採用候補の本文確認を経て別途公開する。
