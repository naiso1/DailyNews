# 外装製品デイリーニュース：初期設定

共通プログラムで内装版・外装版を実行します。未指定は従来の内装版、外装版は `DAILYNEWS_EDITION=exterior` で指定します。収集スクリプトは `--dept exterior`、記事更新スクリプトは `--edition exterior` も受け付けます。不明な版名や不足した外装設定はエラーとして停止します。

## 編集対象

日本・中国・インド・米国・欧州について、グリル、バンパー、外装加飾、発光・照明、エンブレム、レドーム・センサー透過カバー、ウェザーストリップ、関連する材料・成形・塗装・空力を対象にした仮設定です。

外装に関する本文の具体情報を優先します。掲載区分は「製品・技術」と「トレンド・マーケット」の2つです。製品・技術は採用判定「対象」かつ60点以上、トレンドは外装開発に関係するデザイン・市場・規制・材料・競合の変化を対象に65点以上とします。各地域は合計最大10件、トレンドはうち最大4件。詳しい選定順序は[収集・選別方針](COLLECTION_POLICY.md)を参照してください。

条件外の記事による件数補充や、同じ話題の重複による補充はしません。記事がない日もあります。記事元の画像は使えますが、画像のない記事も本文が有用なら掲載できます。2026-09-16の基準見直し後の追加収集は確認中で、公開記事数の増加は未確認です。

## アカウントとメール購読

内装・外装は共通アカウントで利用します。マイページの内装・外装それぞれのチェック欄で、片方だけ・両方・受信なしを選べます。既存の購読状態は維持し、外装からの新規登録は両方オフで開始します。アクセス集計、記事への反応、版ごとの配信先は分離します。詳細は[Webと購読](../../deployment/windows-server/EDITIONS_WEB.md)を参照してください。

## 管理するファイル

| ファイル | 調整する内容 |
| --- | --- |
| `settings.json` | RSS、地域別検索語、同義語、最大件数、最低関連度、画像方針 |
| `prompts/collection.md` | 記事の採用・除外基準 |
| `prompts/insights.md` | 外装向け考察・企画の判断基準 |
| `idea_angles.json` | ヒヤリング後に検討する発想の切り口 |
| `tg_products.json` | 外装開発で検討する製品群の参考リスト |

判定・要約・提案の共通処理はルートの `dailynews/` と既存スクリプトにあります。外装固有の補助判定は `dailynews/exterior.py` です。設定変更だけで調整できない採用条件はここで管理します。

## 保存先

- 公開データ：`content/exterior/`（記事、考察、情報源一覧、記事画像、公開状態）
- 作業データ：`runtime/exterior/`（収集CSV、採用CSV、RSS一覧、処理結果、ログ）
- 共通コード：従来のルートと `ニュース収集/`
- 内装版の既存公開データ・収集履歴は従来の場所を維持します。

両版で同じ記事を採用することはできます。URLの重複履歴、要約キャッシュ、考察・アイデア履歴は版ごとに分離します。CSV内の `内装関連度` などの従来列名は共通処理との互換性のため保持しており、外装実行では外装製品の関連度を表します。

## 画像生成

2026-09-16に企画ID5〜8の4枚の実生成と企画への対応を目視確認済みです。`image_generation.enabled: true`、`provider: exabase` で運用します。初期上限は最新日の先頭4案、1案420秒、全体900秒です。既に画像がある案は再生成せず、同じ日の再実行でも5案目以降へ広げません。過去日へも遡りません。停止する場合は `enabled: false, provider: none` に戻します。

任意のexaBase連携は `dailynews/exabase.py` と `deployment/workstation/exabase/` にあります。1案ごとの企画文・出典IDからプロンプトを組み立て、検証済み画像をその案だけに対応づけます。専用セッションで認証し、キャッシュ、時間制限、結果不明時の再送抑止を行います。画像生成APIへの代替呼び出しはありません。初回確認と有効化は[exaBase連携の運用手順](../../deployment/workstation/exabase/README.md)を参照してください。

## ゼロ件の日と処理失敗

収集結果は `runtime/exterior/collection_result.json` に記録します。正常な情報源取得と新しい採用CSVの出力を確認した場合だけ `completed: true` にします。全RSS取得失敗や、ゼロ件時のLLMエラーは「該当記事なし」として扱いません。

公開側では確認済みの処理日を `content/exterior/publication_status.json` に保存します。ゼロ件の日は過去記事を維持します。日付・版・件数の一致しない収集結果を根拠に、空の更新を成功とすることはありません。

記事がある地域の考察が一部でも未完成なら外装版の更新を失敗とし、公開日を進めません。完成した地域は `runtime/exterior/insights_checkpoint_日付.json` に保存し、同じ記事での再実行時に再利用します。記事がない地域は考察を省略できます。

## メンバーへのヒヤリング

1. 参考になった記事・不要だった記事をそれぞれ5件ほど示してもらう。
2. 製品ごとの優先順位と対象外を確認する。ランプ・空力・ウェザーストリップなどの扱いを明確にする。
3. 量産採用、先行開発、材料、成形技術、競合動向のうち重点を確認する。製品・技術とトレンド・マーケットの比率、過去事例の再紹介をどこまで含めるかも確認する。
4. 必須の企業・媒体・地域・言語を確認する。
5. 考察と企画案の有用性、長さ、欲しい根拠を確認する。
6. 配信頻度と、メールで知りたい情報・サイトで読みたい情報を確認する。
7. exaBaseで生成した企画画像について、検討に役立つか、部品の形状が伝わるか、どの企画に画像が必要かを確認する。現在は最新日の先頭最大4案。実物写真や性能の証拠ではなく、企画のイメージとして評価する。

掲載されなかった候補は `runtime/exterior/selection_review.csv` で採否・点数・理由を確認できる。担当者が候補例を選び、上記1〜3の回答と合わせて収集条件を調整する。
