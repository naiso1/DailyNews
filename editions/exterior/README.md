# 外装製品デイリーニュース：運用設定

共通プログラムで内装版・外装版を実行します。未指定は従来の内装版、外装版は `DAILYNEWS_EDITION=exterior` で指定します。収集スクリプトは `--dept exterior`、記事更新スクリプトは `--edition exterior` も受け付けます。不明な版名や不足した外装設定はエラーとして停止します。

## 編集対象

日本・中国・インド・米国・欧州について、グリル、バンパー、外装加飾、発光・照明、エンブレム、レドーム・センサー透過カバー、ウェザーストリップ、関連する材料・成形・塗装・空力を対象にした仮設定です。

外装に関する本文の具体情報を優先します。掲載区分は「製品・技術」と「トレンド・マーケット」の2つです。製品・技術は採用判定「対象」かつ60点以上、トレンドは外装開発に関係するデザイン・市場・規制・材料・競合の変化を対象に65点以上とします。1号あたり各地域10件、合計50件を目標とし、製品6件・トレンド4件を目安に選びます。一方が不足するときは他方の適格記事で補い、トレンド4件を固定上限にはしません。詳しい選定順序は[収集・選別方針](COLLECTION_POLICY.md)を参照してください。

号の対象日の記事を優先し、不足する地域は当日を含む直近7日以内の未掲載記事から補います。検討候補は1地域最大60件です。記事の元公開日は保持し、掲載する号の日付と分けて管理します。条件外・低得点・同一発表の重複・別の号の既掲載記事による補充はしません。適格記事が足りなければ10件未満とし、足りない分を創作しません。記事元の画像は使えますが、画像のない記事も本文が有用なら掲載できます。

カードは内装版と同じ構成とし、記事区分・トレンド分類・「直近7日から補充」の追加帯は表示しません。記事区分による絞り込みと元公開日の表示は維持し、ヘッダーには号の日付と件数を表示します。

地域は媒体の分類です。例えばインド媒体が紹介した車両を、インド向け発売・採用実績と自動的に扱いません。市場、対象期間、発表・予測・過去事例の区別は記事本文に従います。

2026-09-16の当日記事だけの再評価では、9月15日公開の記事を従来2件から21件へ増やしました（製品・技術14件、トレンド・マーケット7件）。直近7日から補う各地域10件の運用は、その後の見直しです。

## アカウントとメール購読

内装・外装は共通アカウントで利用します。マイページの内装・外装それぞれのチェック欄で、片方だけ・両方・受信なしを選べます。既存の購読状態は維持し、外装からの新規登録は両方オフで開始します。アクセス集計、記事への反応、版ごとの配信先は分離します。詳細は[Webと購読](../../deployment/windows-server/EDITIONS_WEB.md)を参照してください。

## 管理するファイル

| ファイル | 調整する内容 |
| --- | --- |
| `settings.json` | RSS、地域別検索語、同義語、最大件数、最低関連度、画像方針 |
| `prompts/collection.md` | 記事の採用・除外基準 |
| `prompts/insights.md` | 外装向け考察・企画の判断基準 |
| `idea_angles.json` | ヒヤリング後に検討する発想の切り口 |
| `tg_products.json` | 外装開発で検討する製品群の参考リスト |

判定・要約・提案の共通処理はルートの `dailynews/` と既存スクリプトにあります。外装固有の補助判定は `dailynews/exterior.py` です。設定変更だけで調整できない採用条件はここで管理します。

## 保存先

- 公開データ：`content/exterior/`（記事、考察、情報源一覧、記事画像、公開状態）
- 作業データ：`runtime/exterior/`（収集CSV、採用CSV、RSS一覧、処理結果、ログ）
- 共通コード：従来のルートと `ニュース収集/`
- 内装版の既存公開データ・収集履歴は従来の場所を維持します。

両版で同じ記事を採用することはできます。URLの重複履歴、要約キャッシュ、考察・アイデア履歴は版ごとに分離します。CSV内の `内装関連度` などの従来列名は共通処理との互換性のため保持しており、外装実行では外装製品の関連度を表します。

## 画像生成

`image_generation.enabled: true`、`provider: exabase` で運用し、最新号の5地域各2案、既存画像を含めて最大10枚を対象にします。2026-09-15号は企画ID5〜8の4枚を保持し、欧州・中国・インドの企画ID9〜14の6枚を追加しました。ID10は内容確認後に再生成し、最終の計10枚を実生成・目視確認済みです。画像APIは使用していません。画像のない案も文章で公開できます。1案ごとと全体の時間予算を設定し、通常処理では既に画像がある案を再生成しません。同じ号の再実行でも既存画像を上限から差し引き、過去号へも遡りません。停止する場合は `enabled: false, provider: none` に戻します。

任意のexaBase連携は `dailynews/exabase.py` と `deployment/workstation/exabase/` にあります。1案ごとの企画文・出典IDからプロンプトを組み立て、検証済み画像をその案だけに対応づけます。専用セッションで認証し、キャッシュ、時間制限、結果不明時の再送抑止を行います。外装では画像生成APIへの代替呼び出しはありません。画像ごとに生成元を記録し、画面では「AI生成イメージ（exaBase）」と表示します。初回確認と有効化、内装のexaBase優先・API代替設定は[exaBase連携の運用手順](../../deployment/workstation/exabase/README.md)を参照してください。

## ゼロ件の日と処理失敗

収集結果は `runtime/exterior/collection_result.json` に記録します。正常な情報源取得と新しい採用CSVの出力を確認した場合だけ `completed: true` にします。全RSS取得失敗や、ゼロ件時のLLMエラーは「該当記事なし」として扱いません。

公開側では確認済みの号を `content/exterior/publication_status.json` に保存します。補充後もゼロ件の号は過去記事を維持します。号の日付・版・件数の一致しない収集結果を根拠に、空の更新を成功とすることはありません。補充記事の元公開日が号の日付より前でも、対象期間と未掲載条件を満たすかを確認します。

各地域の掲載記事を根拠に、考察と2件ずつの企画例を作ります。記事がある地域の考察が一部でも未完成なら外装版の更新を失敗とし、公開日を進めません。完成した地域は `runtime/exterior/insights_checkpoint_日付.json` に保存し、同じ記事での再実行時に再利用します。根拠記事がない地域は情報不足を明示し、考察や企画を創作して埋めません。

## メンバーへのヒヤリング

1. 参考になった記事・不要だった記事をそれぞれ5件ほど示してもらう。
2. 製品ごとの優先順位と対象外を確認する。ランプ・空力・ウェザーストリップなどの扱いを明確にする。
3. 量産採用、先行開発、材料、成形技術、競合動向のうち重点を確認する。製品・技術とトレンド・マーケットの比率、過去事例の再紹介をどこまで含めるかも確認する。
4. 必須の企業・媒体・地域・言語を確認する。
5. 考察と企画案の有用性、長さ、欲しい根拠を確認する。
6. 配信頻度と、メールで知りたい情報・サイトで読みたい情報を確認する。
7. exaBaseで生成した企画画像について、検討に役立つか、部品の形状が伝わるか、どの企画に画像が必要かを確認する。対象は最新号の各地域2案、既存画像を含めて最大10枚。実物写真や性能の証拠ではなく、企画のイメージとして評価する。

掲載されなかった候補は `runtime/exterior/selection_review.csv` で採否・点数・理由を確認できる。担当者が候補例を選び、上記1〜3の回答と合わせて収集条件を調整する。
